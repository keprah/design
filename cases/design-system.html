Design system

Outcome

  • Built a single design core that makes it faster to maintain different client versions of the product.
  • Simplified interface updates: new states, components and features no longer require rebuilding each mockup from scratch.
  • Redesigned checkout: fewer steps, with the key ordering actions gathered into a more direct and clearer flow.

Starting point

Every restaurant on the platform gets its own client storefront: a menu catalog, a checkout flow and a user account. As the product grew, maintaining these storefronts became harder and harder.

  • mockups were scattered across different sections, which made the structure hard to navigate;
  • brand customization for each client required manual edits;
  • new features had to be repeated in several places;
  • keeping mockups up to date took more and more time as the number of storefronts grew.

The product was scaling, but the design infrastructure could no longer keep up.

Structure and design system

The first step was to organize the mockups. I grouped the interfaces around three key user areas: catalog and listings, checkout, and user account.

This separated the core product structure from client-specific details and made the file easier to navigate for design, management and development.

Variables and components

The design core included color variables, typography, sizing and spacing, base UI components, element states, and components for recurring screens and flows.

Components were bound to variables so that client customization no longer required rebuilding the interface by hand. This made it faster to adapt storefronts to different brands and to maintain product changes centrally.

System logic

The work went beyond visuals. It was important to think through how the design system would live in the real product:

  • which elements should be shared across all storefronts;
  • which parameters can change for a specific client;
  • how to update product flows without chaos in the mockups;
  • how to keep a consistent user experience across different visual settings.

Checkout redesign

Before

  • a multi-step checkout flow;
  • a separate cart as an intermediate step;
  • several sequential screens before payment;
  • re-entering data the system could already know.

After

  • a single checkout screen;
  • cart, delivery details and main actions gathered in one flow;
  • some data pre-filled for signed-in users;
  • straight to payment with no extra steps.

Checkout became more direct: users see their order, check their details, confirm delivery options and go to payment without jumping between screens.

Impact

  • Maintaining mockups got easier thanks to a single design core, and client customization became faster and more predictable.
  • New components and states can be rolled out centrally.
  • Onboarding new clients got simpler through reusable components and variables.
  • Checkout became shorter and clearer for end users, and repeat orders more convenient.
  • The team’s focus shifted from manually rebuilding individual storefronts to developing the shared product core.
